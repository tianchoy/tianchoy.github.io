## 站内搜索二次修复（真正修好，已上线 c3226f1）
上次只补了 `[outputs] home` 让 `/index.json` 能生成，搜索框仍不可用。这次用 Node（vm 加载 lunr 全家桶）+ 无头 Edge（CDP 驱动）逐层定位，发现三个叠加问题：
1. **3.7MB 中文词典卡死初始化**：主题 `lunr.zh.tokenizer` 依赖 `lunr.segmentit`（官方 segmentit 3.79MB），GitHub Pages 实测 15s 仍下不完；而 `theme.js` 必须等该脚本 `onload` 才 `initAutosearch()`，且没写 `onerror` —— 加载不成功搜索就永远不初始化。
2. **查询侧分词口径不一致**：`lunr.zh` 的 `use()` 把 `searchPipeline` 设成英文 Porter stemmer（索引侧却是 trimmer-zh/stemmer-zh），query 词被错误词干化（listtile→listtil、leading→lead）→ 英文也搜不到；且 lunr 查询解析用默认 tokenizer，中文整串当一个 term，与索引 token 对不上。
3. **渲染崩溃**：`autocomplete 0.38.1` 的 `Dataset._render` 调用 `templates.suggestion(suggestion)` 只传 1 个参数，而 theme.js 模板签名是 `(suggestion, { query })`，解构 undefined 抛 TypeError → 有命中却只显示「没有找到结果」。
修复（全部在站点侧，不改主题）：
- 新增 `assets/lib/lunr/lunr.segmentit.js`（同名覆盖主题 3.79MB 文件，5.2KB）：中文按「bigram + 单字」切分，`lunr.segmentit.doSegment` 供索引、`lunr.queryHandler` 供查询（token 加 `+` 强制全部命中），并重写 `lunr.zh` 把 searchPipeline 与索引 pipeline 对齐（覆盖后要手工把 trimmer/stopWordFilter/stemmer/tokenizer 静态属性搬过来，否则 `lunr.zh.trimmer` 变 undefined）。
- 同文件内包装 `window.autocomplete`，给 suggestion 模板补第二个参数 `{ query }`（用 capture 阶段监听 input 记录最近查询）。
- 新增 `assets/data/cdn/jsdelivr.yml`（复制主题文件）注释掉 `autocompleteJS` / `lunrJS` → 回退主题内置本地副本，去掉 jsdelivr 单点。
- `hugo.toml` 显式补 `[params.search]`（enable/type/placeholder/contentLength/maxResultLength/snippetLength），不再依赖主题 config 合并。
- 顺手加 `static/site.webmanifest`（主题 head 引用它，之前 404）。
验证结果（线上复测）：状态栏→1 条精准、父子传值→1、listtile→2、flutter→7 篇去重、雪→3、不存在→「没有找到结果」；控制台无 JS 异常。
部署注意：`deploy.sh` 里 `git push origin main` 走 HTTPS 会被代理 502 拦，改用 `git push git@github.com:tianchoy/tianchoy.github.io.git main`（SSH 已认证）可成功。
