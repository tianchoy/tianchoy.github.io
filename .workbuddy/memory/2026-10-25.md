## 6. 首页滚动条修复（13" MacBook 一屏展示）
- 现象：首页元素很少却有竖向滚动条。
- 根因：主题 `.wrapper` 本就是 `display:flex; flex-direction:column; min-height:100vh`，`main` flex:1、footer 贴底，整页高度本就等于一屏。但上一轮给 `.page.home` 又加了 `min-height: calc(100vh - 3.5rem)`，把内容区撑到近一屏，再叠加底部 footer（GoatCounter 统计+版权）→ 总高超一屏 → 滚动条。

## 7. 仓库设私有导致博客 404、已修复（重要坑）
- 起因：用户想把仓库私有化「防盗」，我误以为 Free 计划也支持私库发布 Pages（错误！）。设为 private 后 Pages 被 GitHub 直接卸载，站点 404（"There isn't a GitHub Pages site here."）。改回 public 后**站点不会自动重建**，仍 404。
- 关键事实：**GitHub Free 计划下，Pages 只能从 public 仓库发布**；private 仓库发 Pages 需 GitHub Pro（$4/月）或迁到 Netlify/Cloudflare Pages。
- 修复：因本地仓库已与 origin 同步、`deploy.sh` 不会再推新提交（无法触发），故手动 `git commit --allow-empty` + `git push origin main`（走已配好的 SSH 443）触发 Actions 重新部署。工作流 `Deploy Hugo site to GitHub Pages` 跑完（conclusion: success），站点恢复 200。
- 验证：`curl -I https://tianchoy.github.io/` → 200。
- 教训：不要轻易把此仓库设 private（会搞挂站点）；若必须私有，需先升级 Pro 或改部署平台。防盗改用「公开仓库 + LICENSE 版权声明」即可。

### 7.1 私有化恢复后又见 README（Pages Source 被重置）
- 现象：站点 200 但显示 README.md 内容，HTML 含 `generator="Jekyll v3.10.0"`、标题取自 README H1。
- 根因：私有化→公开后，GitHub 把 Settings→Pages→Source 从「GitHub Actions」重置回默认的「Deploy from a branch(main/根目录)」；该模式用默认 Jekyll 构建分支，根目录有 README.md 就被渲染成站点。Actions 部署虽成功但没被 serve。
- 修复：Settings→Pages→Source 改回「GitHub Actions」（网页手动，本机无 gh/token 改不了 API）。已先 `git commit --allow-empty` 触发一次成功部署（2a65906）备好 Hugo 产物，用户翻下拉框即生效。
- 教训：仓库私有化会同时搞挂 Pages 并重置 Source；恢复公开后需两步：①触发一次 Actions 部署 ②把 Source 翻回 GitHub Actions。

### 7.2 切回 GitHub Actions 仍显示 Jekyll/README 的真正根因
- 现象：Settings→Pages 已是 GitHub Actions、"Last deployed 2 minutes ago"，但线上仍 `generator="Jekyll v3.10.0"`、`/about/` 404、etag 未变（源站就在服务 Jekyll，非 CDN 缓存，cache-control max-age=600 但 age 仅 104 且 etag 未变）。
- 验证：API 查 Actions run 的 jobs/steps 全 success（Build with Hugo / Upload artifact / Deploy to GitHub Pages 均成功），`deployments` 端点也确认有 github-pages 环境的部署记录（sha 2a659061 等）。说明产物正确且已部署，但**未被当作当前服务版本**。
- 根因：`github-pages` 环境在私有化时被损坏/停用，其 `updated_at` 停在 2025-01-21（私有化前），之后所有部署"写了但不生效"，Pages 回退到分支 Jekyll 构建。
- 待用户执行：Settings→Environments→github-pages→Delete environment（删环境配置+部署历史，不动仓库/内容），删完由我 `git commit --allow-empty` 触发重建部署。
- 教训：仓库私有化会同时搞挂 Pages、重置 Source、并可能损坏 github-pages 环境；恢复三步走：①触发部署 ②Source 翻回 GitHub Actions ③若仍异常则删 github-pages 环境后重建部署。


### 7.3 删环境+重建部署 → 博客彻底恢复（已解决）
- 用户按指引删除了损坏的 github-pages 环境；我 `git commit --allow-empty` 触发重建部署（cc5f773）。
- 验证：工作流 success；线上 `generator="Hugo 0.168.0"`、标题「特严赤傲」、`/about/` 200、站点 200。Jekyll/README 问题彻底消失。
- 完整根因链：设 private（Free 不支持私库 Pages→卸载站点）→ 改回 public（不自动重建→404）→ Source 被重置为 Deploy from a branch（Jekyll 渲染 README）→ 翻回 GitHub Actions（环境已损坏、部署不生效）→ 删 github-pages 环境 + 重建部署（解决）。
- 结论：此仓库绝对不要再设 private；防盗走「公开仓库 + LICENSE」。
