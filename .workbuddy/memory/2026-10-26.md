# 2026-10-26 工作日志

## 安装 GitHub CLI（gh）

- 版本：**gh 2.103.2**，装到 `/opt/homebrew/bin/gh`（与 hugo 同目录），man page 在同级 share/man。
- `brew install gh` **失败**：brew 的 `sandbox_operation.rb extract` 报 `sandbox-exec: sandbox_apply: Operation not permitted`（与当初装 hugo 同一个坑，brew 在此受限环境不可用）。
- 手动安装路径踩的三个坑：
  1. release 资产是 **.zip**（不是 .tar.gz），文件名 `gh_2.103.2_macOS_arm64.zip`。
  2. 环境变量代理 `HTTP(S)_PROXY=127.0.0.1:54518`（WorkBuddy 沙箱代理）**对 github.com release 下载返回 502**；`--noproxy '*'` 直连超时；系统 Clash 代理 127.0.0.1:7897 被沙箱阻断（SSL_ERROR_SYSCALL）。
  3. 解决：用 GitHub 加速镜像 `https://ghfast.top/` 前缀拼接原 URL → 200，下载 14MB 成功。
- `gh auth login --web`（设备码）**不可用**：`POST https://github.com/login/device/code` 经代理返回 **502**，且 `github.com` 主站被代理挡、仅 `api.github.com` 可通（200）。
- 认证方案：复用 macOS 钥匙串里已有的 `gho_` token（40 字符，login=tianchoy，scope：`read:user, repo, user:email, workflow`）。`gh auth login --with-token` 会因**缺 `read:org`** 而拒绝，改用手写 `~/.config/gh/hosts.yml`（权限 600）绕过该校验。
- 结果：`gh auth status` 显示已登录；仅提示 `Missing required token scopes: 'read:org'`（不影响 `gh api` / `gh run` 等实际能力，如需组织操作再 `gh auth refresh`）。
- 已验证能力：`gh api repos/tianchoy/tianchoy.github.io/pages` → `build_type=workflow, status=built`；`gh run list` 正常；`github-pages` 环境已重建（updated 2026-10-25T13:18:58Z）。
- 已知限制：gh 走 `api.github.com`（通），但 device flow / 网页端相关操作依赖 `github.com` 主站（被代理 502），国内网络不稳时会失败。git push 仍走已配的 SSH 443 通道，不受影响。
