# 2026-10-29 工作日志

## 问题1：文章详情页右侧目录「目录」为空（不显示条目）

- 现象：文章页右侧浮动「目录」框只有标题、无条目（截图确认）。
- 排查根因：
  1. KeepIt 主题 `theme.js` 的 `initToc()` 把 Hugo 服务端渲染的 `<nav id="TableOfContents">` 移入 `#toc-content-auto` 并定位右侧浮动框。
  2. 实测 Hugo 0.168 的 `.TableOfContents` **不收录 h4**（`####`）。唯一有标题的文章《青春何处》用的全是 `####`，所以其目录为空。
  3. 尝试 `[markup.goldmark.parser.outline] { title/range }` 配置 —— 经实测（设 `title=h3` 后 h2 仍进目录）确认 **Hugo 0.168 完全忽略该配置**（TOML 合法，但 `hugo config` 不显示、构建不生效），此路不通，已把该配置从 hugo.toml 移除。
  4. 另：38 篇文章里仅 1 篇有标题，其余 37 篇无 h2-h4，原模板会渲染空「目录」框，难看。
- 修复（`layouts/posts/single.html` + `assets/css/_custom.scss`）：
  - 改为**服务端在模板里直接生成目录**：用 `findRE`/`replaceRE` 从 `.Content` 提取 `h2/h3/h4` 标题的 id 与文本，拼成扁平 `<ul class="toc-list">`（按级别加 `toc-h2/h3/h4` 类缩进），注入 `#TableOfContents`（initToc 照常移动/定位）。
  - 仅当文章确实有标题时才渲染目录框；无标题则完全不渲染（不再有空「目录」）。
  - 移除之前尝试的 JS 注入方案（minify 后变量重命名、与 initToc 时序难保证，且静态 HTML 无法验证运行时效果）。
  - `_custom.scss` 加 `.toc-list/.toc-item/.toc-h3/.toc-h4` 缩进与配色（含 dark 主题）。
- 验证：本地 hugo 构建后 `public/posts/随笔/青春何处/index.html` 的 `#toc-content-auto` 内含 5 个真实 `<a href="#...">` 标题链接；`1988` 等无标题文章完全无 toc 框。
- 发布：`bash deploy.sh` 提交 `a303a8c` 推送 `6f09f8d..a303a8c`。
- 备注：Hugo 0.168 对 `.TableOfContents` 的 h4 收录限制 + outline 配置失效，是本博客随笔（常用 #### 分节）目录失效的根因；此服务端方案绕开了它，今后新增 h2-h4 标题都会自动进目录。

## 问题3：右侧浮动目录太难看 → 改为顶部内联可折叠卡片

- 用户反馈：文章详情页右侧浮动目录（KeepIt 默认 `#toc-auto`）太难看；要么换更好看的样式，要么干脆不显示。
- 决定：采用「更好看的样式」路线——把右侧浮窗改成**顶部内联可折叠卡片**，桌面/移动端统一，不再有右侧浮动列。
- 修复：
  - `layouts/posts/single.html`：删除旧的 `#toc-auto`（右侧浮窗）与 `#toc-static`（移动端折叠）两块；改为单个 `<aside class="toc-card"><details open>…</nav>` 卡片，放在正文前。卡片用 `<details open>` 默认展开、可点标题折叠，标题行含图标 + 「目录」+ 右侧 chevron（展开时旋转 180°）。
  - 目录列表沿用服务端生成的 `$tocInner`（已是 `<ul class="toc-list">…</ul>`），卡片 markup 内不再重复包一层 `<ul>`，避免双重 ul 嵌套 bug。
  - `assets/css/_custom.scss`：原 `.toc .toc-list/*` 样式整段替换为 `.toc-card` 卡片样式（圆角边框、浅底、标题行 flex、chevron 旋转、按 h3/h4 级别缩进、hover 高亮、dark 主题配色）。
  - 主题 `theme.js` 的 `initToc()` 依赖 `#TableOfContents`；新卡片不再带该 id，`initToc` 会在 `getElementById('TableOfContents') === null` 处提前 return，不会报错也不会再定位右侧浮窗。
- 验证：`rm -rf public resources && hugo --gc --minify` 构建通过；`public/posts/随笔/青春何处/index.html` 含 `<aside class="toc-card">…<ul class="toc-list"><li class="toc-item toc-h4">…` 且无双重 ul；全站无 `id="toc-auto"/"toc-static"` 残留；CSS 含 `.toc-card*` 规则。
- 发布：`bash deploy.sh` 提交 `16d4708` 推送 `a303a8c..16d4708`。

## 问题4：升级博客程序 Hugo（0.168.0 → 0.169.0）

- 用户问「博客程序版本 + 自动升级」。当前引擎：Hugo v0.168.0 extended（darwin/arm64，本地二进制 `/opt/homebrew/bin/hugo`）；Actions `deploy.yml` 锁定 `hugo-version: "0.168.0"`。官方最新稳定版：**v0.169.0**（2026-10-13 发布）。
- 已确认 0.169.0 无破坏性变更：主要是 Go 1.27.3 安全更新（影响 `resources.GetRemote`，本站未用）、`emojify/plainify` 返回类型收紧、`.Params.title` 等保留字段改走 `.Title` 并告警、menu pre/post 转义。本站模板 grep 确认未踩这些点，libsass 仍在，自定义布局/SCSS/GoatCounter/lunr 均不受影响。
- 升级方式：因**本机沙箱代理会截断大文件下载**（GitHub release 资产单连接最多 ~2.88MB，curl 直连 502、curl Range 0 字节、gh release download 也只拿到 2.88MB/应 42MB、xar/pkgutil/bsdtar 解包因文件被截断而失败）——**本地 42MB 的 Hugo 二进制无法在此环境自动下载升级**。故采用「改 deploy.yml 版本号」完成线上升级：把 `hugo-version: "0.168.0"` → `"0.169.0"`，push 后 GitHub Actions 以 0.169.0 重新构建发布（Pages Source = GitHub Actions，public 不提交，CI 重建）。
- 验证：本地 `rm -rf public resources && hugo --gc --minify` 用 0.168.0 构建通过（确认站点本身无误）；`bash deploy.sh` 提交 `bbd210c` 推送 `5085226..bbd210c`，触发 CI。
- 结论：**线上站点已升到 Hugo 0.169.0**；本地二进制仍为 0.168.0（仅本地预览用，与线上差一个 minor，无碍）。如需本地也升，需用户本机手动：`brew upgrade hugo` 或下载 `hugo_extended_0.169.0_darwin-universal.pkg` 装到 /usr/local/bin 后替换 `/opt/homebrew/bin/hugo`（注意必须 extended 版才能编译主题 SCSS）。
- 顺手更新 `.workbuddy/memory/MEMORY.md`：deploy.yml 版本号、以及「本地二进制无法自动下载升级 + 代理截断」的说明。
