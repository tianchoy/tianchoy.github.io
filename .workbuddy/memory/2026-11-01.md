
## 写作台：Netlify 部署触发 + 删除评论不生效修复（commit 31b315a）
- **新增 `lib/netlify.mjs` + `/comments` 页底部「评论服务部署（Netlify）」卡片**：填一次密钥后点按钮即可 Trigger deploy，不用再去 Netlify 后台。
  - 两种触发方式二选一：① Build Hook URL（`POST https://api.netlify.com/build_hooks/<id>`，body `{}`，返回 201）；② Personal Access Token（走官方 API `GET /api/v1/sites?name=<站点名>` 换 site id → `POST /api/v1/sites/{id}/builds`；还能 `GET /api/v1/sites/{id}/deploys?per_page=3` 查状态）。优先用 build hook。
  - **站点名从 hugo.toml 的 `params.page.comment.waline.serverURL` 推导**（`*.netlify.app` 前缀），当前 = `wondrous-chimera-eeddf5`；部署记录页 `https://app.netlify.com/sites/<name>/deploys`。
  - 密钥存 `.deploy-auth.json`（已加 .gitignore），**不回显**：输入框留空 = 保持原样，只有 `reset:true` 才清空。
  - 路由：`GET /api/netlify`、`POST /api/netlify/config`、`POST /api/netlify/deploy`、`GET /api/netlify/state`。
- **「删除后刷新还在」的根因与修法**：不是缓存（Waline 响应 `cache-control: no-cache`、Netlify `cache-status: fwd=bypass`，本地 `sendJSON` 也是 `no-store`）。真正问题是**删除请求失败时前端毫无反馈**——`doDelete` 抛错后不调 `load()`，旧行原样留在表格里，红色 toast 一消失就像没发生过，而成功时才会留下绿色 `已删除 N 条` 横幅（截图里没有横幅 = 那次删除确实失败了）。三处改动：
  1. `lib/comments.mjs` 的 `request()` 加重试：45s 超时 + 对 408/425/429/500/502/503/504/522/524 与网络错误重试 2 次（Netlify 函数包体 200MB+，冷启动偶发超时）。
  2. 删除改成**乐观更新**：接口返回成功先把行从 `items` 摘掉渲染，再 `load({verify})` 拉真实数据**核对**；若已删 id 仍在返回里，弹红色「❌ 删除未生效，服务端仍然返回这些评论」。
  3. 服务端 `/api/comments/delete` 把逐条失败原因拼进顶层 `error`，前端再也不显示没信息量的「删除失败」。
  - 验证方法：临时 `FAKE_DELETE=1` 让 `deleteComment` 变空操作 → 页面正确报「删除未生效」；正常路径自动点击测试 1 行 → 0 行 + 绿色横幅。
- 调试页面交互的技巧：把 `comments.html` 复制成 `web/__test.html`，去掉 `confirm(...)` 并在 `</body>` 前塞一段自动点击 + 写 `<pre id="__log">` 的脚本，临时加一条 PAGES 路由，用 Edge `--headless=new --dump-dom --virtual-time-budget` 读回 DOM 断言（**记得用完删掉临时文件和路由**）。
